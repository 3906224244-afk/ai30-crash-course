## 二、原子接口依赖关系表

| 接口名 | 作用 | 前置条件 | 关联组件 | 后续调用 |
|--------|------|---------|---------|---------|
| `getSocialAdvice` | 核心咨询流程：分流→追问→生成策略 | situation 非空；phase 正确标识当前阶段；answers 携带历史问答（无则空数组） | split-card / question-card / strategy-list-card | 自身（多轮追问或重新生成） |
| `querySocialRule` | 查询社交礼仪规则/行情 | ruleType 非空；用户意图明确为规则查询而非沟通咨询 | knowledge-card | 无（单轮结束） |

| 外部依赖 | 说明 |
|---------|------|
| `storage` 接口 | 读取用户在小程序端录入的人设档案（profile），用于个性化策略生成 |
| 知识库 | 社交规则、沟通策略框架、案例数据。已升级为 ZhipuAI embedding-3（1024维）向量检索，余弦相似度>0.35返回top-N匹配规则。Ask 和 Generate 阶段均通过 RAG 预检索注入知识库 compact 摘要 |

## 三、业务约束

### 执行顺序（铁律）

1. **先分流再追问**：首次调用必须经过 split 阶段确认用户模式，不得跳过追问直接生成
2. **追问最多5轮**：第1轮固定为自由叙述（让用户把故事讲完），第2-5轮为选择题追问（最多4道）。answers 数组长度达到5时，无论信息是否齐全都必须进入 generate
3. **追问不能为空转**：每轮追问必须覆盖至少一个新的信息维度，不得重复问已回答的维度
4. **generate 只能调用一次**：5条策略生成后此轮咨询结束；用户若要重新生成需明确表达重新开始的意图
5. **querySocialRule 不参与多轮**：查规则是单次调用，不产生追问链

### 输出形态（铁律）

1. **事实+动作两段式**：所有返回必须包含 fact 和 action 两个字段，缺一不可
2. **禁止裸指令**：action 必须引导AI展示本接口返回的卡片数据，不得只描述卡片内容而不指向卡片数据
3. **禁止纯文本输出**：绑定组件的接口必须返回卡片数据（card字段），不得以纯文本替代
4. **枚举值英文**：phase 等枚举字段必须使用英文枚举值，不得使用中文 label

### 数据来源（铁律）

1. **situation 必须来自用户原话**：不得改写、概括、或过滤用户语气词
2. **answers 必须来自对话历史**：不得自行编造问答对
3. **profile 必须来自 storage**：不得猜测或填充用户未录入的信息
4. **ruleType 必须可归类**：无法归类的用户提问，将原始提问原文作为 ruleType 传入

### 安全边界

1. **涉及人身安全、违法行为时**：拒绝生成建议，引导用户寻求专业帮助（报警、心理咨询等）
2. **PUA、精神控制、隐私窃取类请求**：拒绝并警告
3. **AI建议翻车后果大于代码翻车**：社交翻车直接影响用户真实关系，策略生成必须保守，不得给极端建议

### 组件约束

1. **卡片比例**：4:1（最小高度）至 1:1（最大高度）
2. **禁止竖向滚动**：卡片内容超出高度时必须精简或分页
3. **禁止动画**：卡片无动画效果
4. **必须关联页面**：组件 `created` 中通过 `setRelatedPage` 设置关联的小程序页面

## 四、用户意图分流表

| 用户表达（触发词） | 意图类型 | 调用接口 | 说明 |
|-------------------|---------|---------|------|
| "帮我回一下"、"怎么回"、"怎么跟他说"、"帮我措个辞"、"该怎么说"、"这样回合适吗"、"不知道怎么开口"、"纠结怎么回"、"帮我组织语言"、"帮我想个理由" | **沟通咨询** | `getSocialAdvice` (phase=auto) | 核心场景。用户需要面对一个具体的人进行沟通 |
| "怎么回复领导/导师/暧昧对象"、"被阴阳了怎么回"、"得罪人了怎么道歉"、"怎么追人开场" | **沟通咨询** | `getSocialAdvice` (phase=auto) | 指定了对象和场景的沟通需求 |
| "随份子多少钱"、"敬酒怎么说"、"送礼送什么"、"见家长注意什么"、"红包包多少" | **规则查询** | `querySocialRule` | 纯行情/规则查询，不需要人设 |
| "帮我写一篇演讲稿"、"写个文案"、"怎么写邮件" | **不匹配** | 不调用本Skill | 非人际沟通，属于内容创作 |
| 用户既问了规则又描述了具体沟通场景 | **沟通咨询优先** | `getSocialAdvice` | 当意图模糊时，优先走沟通咨询（含追问可以覆盖规则需求） |

### 分流判断逻辑（getSocialAdvice 内部）

| 条件 | phase 取值 | 说明 |
|------|-----------|------|
| 用户首次匹配，尚未描述场景 | `split` | 返回分流卡片（急需答案/提前录入） |
| 用户已描述场景，answers 为空 | `ask` | 返回自由叙述卡片（让用户把故事讲完，含directionHints引导） |
| answers 长度 1-4，信息缺口未补全 | `ask` | 返回选择题追问卡片（A/B/C定向+D自由输入，最多4道） |
| answers 已覆盖全部信息缺口，answers长度≥5，或用户明确表达"出结果" | `generate` | 返回5条策略卡片（流式输出） |
| 以上条件均无法判断 | `auto` | 工具自行分析缺口决定 |
